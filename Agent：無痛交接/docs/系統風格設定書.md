# 接續介面風格標準

版本：1.0  
更新日期：2026-07-22  
適用範圍：接續網站、後續功能頁、展示原型與產品文件

## 1. 品牌核心

### 品牌定位

「接續」是一個協助團隊傳承工作脈絡的知識交接產品。介面不只要有效率，也要降低新人面對大量資訊時的焦慮。

### 視覺關鍵字

- 溫和：低飽和色彩、柔軟圓角、適度留白。
- 可信：清楚呈現來源、狀態、負責人與風險，不使用誇張承諾。
- 有脈絡：使用關聯線、節點、步驟與層級，表達資訊之間的關係。
- 安定：避免強烈純色、大面積高對比與過度動態效果。

### 設計原則

1. 先給方向，再給細節：首頁先回答「今天要做什麼」，深入頁面再呈現脈絡與來源。
2. 重要資訊可追溯：AI 回答、風險提醒與決策說明都應附上來源。
3. 提醒而不製造焦慮：危險色只用於真正需要處理的事項，避免整頁紅色警告。
4. 降低一次性資訊量：以清單、卡片、分段與漸進揭露拆解複雜內容。
5. 每個狀態都能理解：避免只靠顏色，搭配文字、圖示或狀態標籤。

## 2. 色彩系統

### 核心色票

| Token | 色碼 | 用途 |
| --- | --- | --- |
| `--ink` | `#24332D` | 主文字、深色標題 |
| `--muted` | `#6D7B74` | 次要文字、說明文字 |
| `--sage` | `#567766` | 品牌主色、主要按鈕、完成狀態 |
| `--sage-dark` | `#3F5F50` | 主色 hover、強調文字 |
| `--sage-soft` | `#E7EEE8` | 選取背景、提示區、柔和標籤 |
| `--paper` | `#FFFEFB` | 主要卡片與內容表面 |
| `--canvas` | `#F3F5F1` | 全頁背景 |
| `--line` | `#DFE5E0` | 邊框、分隔線 |
| `--sand` | `#F1E7D4` | 決策、經驗與人性化內容 |
| `--blue-soft` | `#E4EDF0` | 次要資訊、系統相依項目 |
| `--danger` | `#A85E55` | 高風險、缺漏、衝突 |
| `--warning` | `#AF7C39` | 中度風險、待補資訊 |

### 背景層級

- 頁面底色：`#F3F5F1`
- 左側導覽：`#F9FAF7`
- 右側 Agent：`#FBFCF9`
- 主要卡片：`#FFFEFB`
- 次要容器：`#F6F8F4` 或 `#F7F8F5`
- 遮罩：`rgba(32, 45, 38, 0.28)` 加上 `blur(7px)`

### 狀態色使用規範

- 成功／完成：`--sage` 文字或底色，搭配「完成」或勾選符號。
- 資訊／選取：`--sage-soft` 背景配 `--sage-dark` 文字。
- 警告／待補：淺沙橘背景 `#F5EAD8` 配 `--warning`。
- 危險／高風險：淺粉紅背景 `#F3E3E0` 配 `--danger`。
- 禁止以紅色作為一般裝飾色。

### 色彩比例

- 70% 中性淺色：畫布、卡片、留白。
- 20% 鼠尾草綠：品牌、選取、完成、主要動作。
- 10% 沙色、霧藍與狀態色：分類與提醒。

## 3. 字體與文字層級

### 字體家族

介面與內文：

```css
font-family: "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", system-ui, sans-serif;
```

品牌名稱、主標題、數字亮點與引用：

```css
font-family: Georgia, "Noto Serif TC", serif;
```

### 建議層級

| 層級 | 尺寸 | 字重 | 行高 | 使用位置 |
| --- | --- | --- | --- | --- |
| Display | `28-43px` | 500 | 1.28 | 首頁核心標題 |
| Page title | `26-39px` | 500 | 1.35 | 功能頁標題 |
| Section title | `20px` | 500 | 1.4 | 區塊標題 |
| Card title | `12-14px` | 700 | 1.4 | 卡片與清單主文字 |
| Body | `12-14px` | 400 | 1.65-1.75 | 說明與內容 |
| Label | `10-11px` | 700 | 1.4 | 按鈕、導覽、欄位標籤 |
| Caption | `9-10px` | 400 | 1.5 | 來源、時間、輔助資訊 |
| Eyebrow | `10px` | 800 | 1.4 | 區塊分類標籤，字距 `0.12em` |

目前展示版使用較緊湊的 `8-12px` 介面文字。後續正式功能頁應以 `14px` 作為一般內文下限，關鍵操作文字不得小於 `12px`。

### 排版規則

- 中文主標題可使用襯線字體，最多兩行。
- 一般說明每行建議不超過 42 個中文字。
- 標題使用句號或完整短句，避免全形驚嘆號堆疊。
- 英文只作輔助，例如品牌副標；產品主資訊以繁體中文為主。
- 數字與百分比可使用 Georgia，形成安定的資料亮點。

## 4. 間距、尺寸與圓角

### 基礎間距

後續開發以 4px 為基準單位：

| Token | 值 | 常見用途 |
| --- | --- | --- |
| `space-1` | `4px` | 圖示與小標籤內距 |
| `space-2` | `8px` | 緊密元素間距 |
| `space-3` | `12px` | 清單與小卡片內距 |
| `space-4` | `16px` | 一般元件間距 |
| `space-5` | `20px` | 卡片內部區塊 |
| `space-6` | `24px` | 主要卡片 padding |
| `space-7` | `28px` | 桌面工作區 padding |
| `space-8` | `32px` | 大區塊間距 |
| `space-10` | `40px` | Hero 與頁面段落 |
| `space-12` | `48px` | 大型版面留白 |

### 圓角

| Token | 值 | 使用位置 |
| --- | --- | --- |
| `radius-sm` | `8px` | 圖示、迷你按鈕 |
| `radius-control` | `10px` | 一般按鈕、輸入框 |
| `radius-card` | `12-14px` | 小卡片、提示框 |
| `radius-panel` | `17px` | 主內容面板 |
| `radius-hero` | `22px` | Hero 與大型主視覺 |
| `radius-pill` | `999px` | 標籤、狀態、進度膠囊 |

同一層級的元件應使用相同圓角。不要在一般功能頁加入尖銳直角卡片。

### 控制元件尺寸

- 正式產品按鈕與可點擊區域：最小高度 `40px`，觸控版最小 `44px`。
- 圖示按鈕：桌面至少 `34px`，觸控版至少 `44px`。
- 主要輸入框：最小高度 `44px`。
- 狀態標籤：高度約 `24-28px`。

## 5. 陰影與層級

| 層級 | 陰影 | 使用位置 |
| --- | --- | --- |
| Base | `0 9px 28px rgba(48, 65, 56, 0.045)` | 一般面板 |
| Raised | `0 16px 45px rgba(42, 60, 51, 0.08)` | Hero、重要卡片 |
| Control | `0 8px 20px rgba(63, 95, 80, 0.16)` | 主要按鈕 |
| Overlay | `0 25px 80px rgba(31, 47, 38, 0.22)` | Modal |

陰影必須帶綠灰色調，避免純黑重陰影。一般頁面最多同時使用三個可感知層級。

## 6. 版面系統

### 桌面版

```text
左側導覽 218px | 中央工作區 minmax(560px, 1fr) | Agent 330px
```

- 頂部列高度：`68px`
- 工作區 padding：`28px`
- Hero：文字區加 `250px` 進度視覺區
- 次要內容：`1.1fr / 0.9fr` 雙欄
- 導覽與 Agent 固定在視窗高度內，中央工作區獨立捲動。

### 響應式斷點

| 寬度 | 規則 |
| --- | --- |
| `>1180px` | 完整三欄，左 218px、右 330px |
| `<=1180px` | 左 200px、右 295px，工作區 padding 22px |
| `<=980px` | 左側收合為 82px；隱藏次要說明；複雜內容改單欄 |
| `<=760px` | 單欄；導覽改為底部 68px；Agent 移至主內容下方；工作區 padding 15px |

### 卡片網格

- 摘要卡片：桌面三欄，手機單欄。
- 主卡片間距：`16-18px`。
- 卡片內容 padding：小卡 `14-16px`、一般面板 `22-30px`、Hero `34-38px`。

## 7. 元件標準

### 主要按鈕

- 背景：`--sage`
- 文字：白色
- 圓角：`10px`
- 字重：700
- Hover：背景改為 `--sage-dark`，向上位移 `1px`
- 用於：繼續流程、送出、加入資料等主要行動
- 每個可視區域原則上只有一個主要按鈕。

### 次要按鈕

- 白色背景、`#CCD7CF` 邊框、`--sage-dark` 文字。
- 不使用明顯陰影。
- 用於：檢查、查看、取消以外的次要行動。

### 文字按鈕

- 使用 `--sage`，可搭配右箭頭。
- 不加底線，hover 時可降低亮度或增加下底線。
- 用於卡片右上角的「查看全部」、「打開地圖」。

### 面板與卡片

- 面板背景使用 `--paper`。
- 一般面板圓角 `17px`，邊框 `1px solid #E0E5E1`。
- 小卡片圓角 `12-14px`。
- 卡片內資訊順序：分類標籤 → 標題 → 說明 → 狀態／來源 → 行動。

### 狀態標籤

- 使用膠囊形狀。
- 必須同時顯示文字，例如「待補」、「高」、「已完成」。
- 顏色只作為第二層提示，不是唯一辨識方式。

### 表單與輸入框

- 白色背景、`#CFD9D1` 邊框、`10-13px` 圓角。
- Focus：邊框 `#8FA697`，外圈 `0 0 0 3px rgba(86, 119, 102, 0.08)`。
- Placeholder 使用低對比灰綠色，但輸入內容需維持可讀性。
- 錯誤狀態需提供文字原因與修正方式。

### Modal

- 最大寬度約 `620px`。
- 圓角 `21px`，padding `34px`。
- 背景遮罩使用深綠灰透明色與模糊效果。
- 步驟流程需提供明確返回與關閉操作。
- 手機版改為單欄選項，padding 降至 `20-28px`。

### Agent 對話

- Agent 訊息：白底、細邊框、左上角較小圓角。
- 使用者訊息：品牌綠底、白字、右上角較小圓角。
- AI 回答下方應呈現來源或錨定信心。
- 資訊不足時應直接說明，並建議詢問對應負責人。
- 永遠保留「重要決策請查看原始來源」等防呆文字。

### 企劃地圖

- 畫布使用淺色點陣背景。
- 人員、任務、決策以色彩和文字雙重分類。
- 主節點使用品牌綠；次節點使用白、沙色或霧綠。
- 選取狀態使用邊框與輕微浮起，不靠放大或閃爍。
- 節點詳情必須包含：類型、名稱、說明、負責人或來源。

### 路線圖

- 使用垂直順序線與圓形步驟。
- 完成項目：品牌綠實心圓、勾選符號、文字弱化。
- 當前項目：淺底色、細邊框與「建議接著做」標籤。
- 點擊完成後仍可回復，避免不可逆操作。

### 風險卡片

- 結構：風險等級 → 標題 → 原因／影響 → 來源／負責人 → 查看詳情。
- 高風險使用紅棕色，中風險使用沙橘色，提示使用鼠尾草綠。
- 避免只寫「發生錯誤」，應說明歷史事件、影響與建議預留時間。

## 8. 圖示與視覺語言

- 圖示以簡單線性或單色符號為主。
- 圖示容器常用 `8-10px` 圓角與 `--sage-soft` 背景。
- 同一畫面不可混用填色 3D 圖示、手繪圖示與線性圖示。
- 裝飾圖形使用圓、弧線、節點與柔和關聯線，呼應「知識延續」。
- 避免大面積人物照片或過度科技感的藍紫漸層。

## 9. 動態與互動

- 一般 hover／狀態切換：`200ms ease`。
- 卡片 hover：最多向上 `2px`。
- Modal 進場：淡入加向上 `12px`，約 `180-220ms`。
- 禁止持續閃爍、彈跳或大幅縮放。
- 必須支援 `prefers-reduced-motion: reduce`，停用非必要動畫。

## 10. 文案語氣

### 語氣原則

- 像可靠的同事，不像命令式系統。
- 先讓使用者知道「現在可以做什麼」，再說明原因。
- 使用短句與具體動詞：整理、查看、核對、繼續、補齊。
- 避免「立即革命」、「完美解決」、「百分之百正確」等誇張承諾。

### 推薦句型

- 「不用一次看完，照這個順序就好。」
- 「重要的脈絡，都幫你接好了。」
- 「這項提醒來自 05/26 成長會議。」
- 「目前資訊不足，建議向林家豪確認。」
- 「為什麼這樣安排？」

### 避免句型

- 「警告！你做錯了！」
- 「AI 已替你完成所有決策。」
- 「系統無法處理。」
- 只顯示代碼或技術錯誤，未提供下一步。

## 11. 無障礙標準

- 文字與背景對比至少符合 WCAG AA。
- 焦點狀態不可只靠瀏覽器預設，也不可被移除。
- 圖示按鈕必須提供可讀的 `aria-label`。
- Modal 使用 `role="dialog"`、`aria-modal="true"` 並管理焦點。
- 狀態不能只靠色彩；加入文字、圖示或形狀。
- 鍵盤操作順序需與視覺閱讀順序一致。
- 觸控區域至少 `44 × 44px`。
- 動畫遵守使用者的減少動態偏好。

## 12. 開發規範

### CSS Token

新元件不可直接新增近似品牌色，應先使用既有 Token：

```css
:root {
  --ink: #24332d;
  --muted: #6d7b74;
  --line: #dfe5e0;
  --paper: #fffefb;
  --canvas: #f3f5f1;
  --sage: #567766;
  --sage-dark: #3f5f50;
  --sage-soft: #e7eee8;
  --sand: #f1e7d4;
  --blue-soft: #e4edf0;
  --danger: #a85e55;
  --warning: #af7c39;
  --shadow: 0 16px 45px rgba(42, 60, 51, 0.08);
}
```

### 命名原則

- 元件名稱反映功能：`RiskCard`、`RoadmapItem`、`SourceChip`。
- 樣式名稱使用元件或語意，不使用顏色名稱：使用 `status-warning`，避免 `orange-label`。
- 狀態以 `is-active`、`is-done`、`is-disabled` 或對應屬性表示。

### 新元件審查清單

- 是否使用既有色彩、字體、圓角與陰影？
- 是否只有一個清楚的主要行動？
- 是否提供 hover、focus、disabled、loading、error 狀態？
- 是否在 1180px、980px、760px 三個斷點正常顯示？
- 是否能使用鍵盤完成主要操作？
- 是否在資訊不足或失敗時提供下一步？
- AI 內容是否顯示來源或信心資訊？
- 是否避免讓小字成為主要閱讀內容？

## 13. 不可偏離項目

以下項目構成「接續」目前的核心視覺辨識，除非整體品牌改版，後續功能應保持一致：

1. 米白與淺灰綠背景，不使用純白滿版。
2. 鼠尾草綠作為唯一主要品牌色。
3. 主標題使用人文感襯線字，介面使用清晰無襯線字。
4. 卡片採細邊框、柔和陰影與中高圓角。
5. AI 回答可追溯來源，風險提示具體且不恐嚇。
6. 桌面維持「導覽／工作區／Agent」三欄概念；手機改為單欄與底部導覽。
